Your First Claude Code Session

GitHub setup, importing the starter project, and learning the key commands.

You've got Claude Code running. Now let's get the starter project on your machine and learn how to work with Claude effectively.

Setting Up GitHub

GitHub is where code lives — think of it like Google Drive, but for code. Every version of your project is saved there, so you never lose work. You'll need an account.

Create a GitHub Account

Go to github.com and sign up. Use your email, pick a username, and you're done. The free plan is all you need.

Fun fact: You can also ask Claude Code to help you set up Git on your machine. Just type claude in your terminal and ask: "Help me set up Git and connect it to my GitHub account."

Install Git

Git is the tool that connects your computer to GitHub. Download it from git-scm.com and install with all the defaults (Next, Next, Finish). Or simply ask Claude Code — it can guide you through the entire process.

git --version
What you should see: Something like git version 2.x.x. If you see this, Git is installed correctly.

Clone the Starter Project

The starter project is already built and waiting for you on GitHub. "Cloning" means downloading a copy to your computer. Make sure you're in your Projects folder, then:

git clone https://github.com/ashishefe/Bank-Summary-Creator.git cd Bank-Summary-Creator
What you should see: Files downloading, then your terminal prompt shows you're inside the Bank-Summary-Creator folder. This is your project — everything you build lives here.

Key Claude Code Commands

Claude Code has a few commands that make working with it much smoother. Here are the ones you'll use most:

claude — Start a Conversation

Type claude in your project folder to start talking to Claude. It reads your project files, understands the code structure, and is ready to help. Think of it as opening a chat with a developer who already knows your project.

cd Bank-Summary-Creator claude

/init — Initialize Project Context

When you start Claude Code in a project for the first time, type /init. This creates a CLAUDE.md file — Claude's memory of your project. It records what the project does, how it's structured, what commands to use. Every time you start a new conversation, Claude reads this file to remember the context.

Why this matters

Without CLAUDE.md, Claude starts fresh every conversation. With it, Claude remembers your project's conventions, file structure, and how things work. It's like giving a new team member the onboarding doc.

/plan — Think Before Acting

This is the most important command. /plan tells Claude to think through the task before writing any code. It will read relevant files, consider the approach, and present a plan for your approval. You review the plan, suggest changes, and only then does Claude start coding.

This is how professionals work — plan first, execute second. It prevents Claude from going down the wrong path and wasting time.

/cost — Check Usage

Curious how much you've used? Type /cost to see your usage for the current session. With Claude Max, you have generous limits — but it's good to keep an eye on it, especially while learning.

The CLAUDE.md File

This deserves its own section because it's a powerful concept. CLAUDE.md is a file in your project that acts as Claude's persistent memory. It contains:

  • Project overview — what the tool does, in one paragraph
  • Key commands — how to run the app, run tests, install dependencies
  • Architecture notes — how the code is organized, where things live
  • Conventions — coding style, naming patterns, design decisions

The starter project already has a CLAUDE.md. As you build and evolve the project, Claude will update this file to reflect new decisions and patterns. It's a living document.
