You're Off to the Races

Everything is set up. Here's how to start building.

You have Claude Code installed, the starter project cloned, and you understand the key commands. Now it's time to start building Phase 1 of your tax tool.

Your First Real Task

Open your terminal, navigate to the project folder, and start Claude Code:

cd Projects\Bank-Summary-Creator claude

Once Claude is running, type /plan to enter plan mode, then paste the contents of the PRD (the product requirements document that's already in your project at tasks/PRD.md). Or simply tell Claude:

Read tasks/PRD.md and plan Phase 1 implementation

What Happens Next

Claude will:

  1. Read the PRD — it understands the full scope of what you're building
  2. Read the existing code — the starter project already has working bank parsers, a categorizer, and an Excel generator
  3. Ask clarifying questions — "Should I focus on session persistence first, or parser reliability?" Answer based on what matters most to you
  4. Propose a plan — a step-by-step breakdown of what it will build, in what order
  5. Wait for your approval — you review the plan, suggest changes, and give the green light

Then Claude starts coding. It writes files, runs tests, fixes bugs — and checks in with you when it needs decisions.

Tips for Working with Claude Code

  • Be specific about what you want. "Add a button to download the Excel file" is better than "make it better." The more context you give, the better the result.
  • Review plans before approving. When Claude proposes a plan, read it. If something feels off — "why are you changing that file?" — ask. It's much cheaper to fix a plan than to fix code.
  • Test as you go. After Claude makes changes, ask it to run the tests: "Run the tests and show me the results." This catches problems early.
  • If something breaks, describe the error. Copy the error message and paste it to Claude. "I see this error when I upload a PDF: [error text]." Claude will diagnose and fix it. That's literally what it's best at.
  • Use your domain knowledge. "The opening balance for SBI statements sometimes appears in a different row" — this kind of insight from your experience is exactly what makes the tool better. Claude handles the code; you handle the "what should happen."
  • Save your work with Git. Periodically ask Claude: "Commit the current changes." This saves a snapshot of your work on GitHub. If anything goes wrong, you can always go back.
